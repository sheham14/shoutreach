ShoutReach

Personal project · Built May 2026 · Python / Flask / SQLite / Vanilla JS

A self-hosted cold email outreach platform built from scratch as a production-grade alternative to tools like Instantly and Smartlead. Runs as a single Flask process on any Linux server — unlimited contacts, unlimited campaigns, full data ownership, no vendor lock-in.

Why I built it: Existing tools charged $100+/month, stored my data on their servers, and locked AI features behind a markup. ShoutReach solves all three — self-hosted, bring-your-own SMTP, bring-your-own AI key. Key technical differentiators: campaign-level template variables for city-targeted batches, DNS MX validation with invalid emails surfaced as sales signals, and RFC 3834-compliant auto-reply filtering so OOO replies don't stop sequences.

Variables System

Variables follow {{variable_name}} syntax. Three layers — highest priority wins:

Priority Order (highest → lowest)

PrioritySourceExampleOverride
1 — HighestStandard contact fields{{first_name}}, {{company}}Always wins
2 — MiddleContact extra JSON (from CSV columns){{job_title}}, {{industry}}Overrides campaign vars
3 — LowestCampaign variables (key-value in settings){{location}}, {{niche}}Falls back if no contact-level value

Standard Contact Variables

VariableValue
{{first_name}}Contact's first name
{{last_name}}Contact's last name
{{full_name}}First + last combined
{{company}}Company name
{{email}}Contact email address

Contact Custom Fields (from CSV)

Any non-standard CSV column is stored in the contact's extra JSON field. Example CSV:

email,first_name,company,job_title,industry
drsmith@dental.com,John,Smith Dental,Owner,Dentistry

Use in template: {{job_title}}, {{industry}} — each contact has its own value.

Campaign Variables

Set in Campaign → ⚙ Settings → Campaign Variables. Useful for city-targeting batches:

location = Brampton
niche    = dental practices

Use: Hi {{first_name}}, I came across {{company}} while looking at {{niche}} in {{location}}...

Note: If a contact has a custom field with the same name as a campaign variable (e.g. location in their CSV row), the contact value wins. Campaign variables are the fallback.

Scheduler flow

Every 60s → process_queue()
  → for each active campaign:
      → is_business_hours(campaign)?  ← timezone-aware
      → daily cap reached?
      → bounce rate > threshold?  ← auto-pause
      → get_due_enrollments()
      → for each enrollment:
          → pick step → pick variant
          → parse campaign variables JSON
          → send_email(contact, subject_tpl, body_tpl, campaign_vars=...)
              → _render(template, contact, campaign_vars)
                  → merge: campaign_vars < extra JSON < std fields
          → advance or complete enrollment
          → sleep random(min_delay, max_delay)

Every 5m → check_replies() + check_bounces()
  → IMAP scan all accounts
  → _is_auto_reply() filter (RFC 3834)
  → mark_enrollment_replied() for genuine replies
